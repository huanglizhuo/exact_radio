# 「世界」页地图交互设计（草案，未落地）

> 结论先说：现在拖地图**确实**会触发换台逻辑，但它有三处设计缺陷 —— 触发没有阈值、等待期没有任何反馈、
> 结果不可见 —— 所以体感上像「没反应」。下面先给出诊断，再给两套交互方案。

## 一、现在的实际行为（实测）

| 用户动作 | 现在的行为 |
| --- | --- |
| 拖动地图（哪怕 6×4 像素） | `pointerup` → `settleRev += 1` → 查 `geo_distance` 最近的台 → 自动播放 |
| 轻点地图（不拖） | **同样**触发换台（`globeUp` 无条件执行） |
| 松手后 0.5–2 秒 | 界面完全不动：`busy` 只在 ⏭ 按钮（`tuning`）和飞行（`spinning`）时为真，网络等待期没有状态 |
| 结果返回 | 地图 `spinTo` 滑到那个台（约 630ms），播放条换成新台 |
| 附近没有台（>3000km） | **什么都不发生**，没有提示，`settleRev` 一直停在 >0 |
| 滑动动画中再拖 | `task settle` 要求 `not spinning`，所以这一次拖动被吞掉，看起来"拖不动/没反应" |

对应代码位置（当前 `app.contract`）：

- `action globeUp`：`dragging = false` + `settleRev = settleRev + 1`，没有位移阈值。
- `resource nearby = nearest(globeLat, globeLon) when settleRev > 0`。
- `task settle when not dragging and settleRev > 0 and nearby.length > 0 and not spinning` → `after(80, playNearby)`。
- `derive busy = tuning or spinning` —— **没有包含「查询中」**。

## 二、设计目标

1. **拖动是浏览，不是命令**：手指划过地图不应该一路换台。
2. **每一次「有结果/没结果」都要看得见**：等待要有骨架或转圈，没结果要有话术，不要静默。
3. **用户选的位置要留在屏幕上**：现在松手后地图直接飞走，用户失去"我选的是这里"的锚点。
4. **距离要可解释**：调频台是"最近的那个"，但用户想知道它有多远、还有没有更近的。

## 三、方案 A（推荐）：「松手看看这一带」

```
手指按下 ─────────► 拖动：地图跟手，中央准星 + 顶部提示「松手看看这一带」
   │
   └─ 松手（位移 ≥ 24pt）─► 立即出现「正在查看这一带…」卡片（骨架 + 转圈）
                                │
              ┌─────────────────┴─────────────────┐
        有结果（按距离升序 ≤ 10 条）          没有结果
              │                                  │
   底部卡片列出：距离 · 台名 · 国家        「这一带 300 公里内没有登记在册的电台」
   正在播的那台带 ✓ 和「正在播放」         [ 扩大范围到 1,000 公里 ] [ 回到当前电台 ]
              │
        点一行 ─► 播放 + 地图飞过去 + 落一个固定 pin
```

- **位移阈值 24pt**：小于阈值当作点击，什么都不做（只把准星点亮一下）。
- **查询半径随缩放走**：按当前 zoom 的"屏幕可视直径"取半径（zoom 3 ≈ 1500km、5 ≈ 400km、7 ≈ 100km），
  这样"屏幕里看到的范围"和"搜到的范围"是同一个空间概念。
- **等待期双反馈**：底部卡片进骨架态（3 行灰条 + 「正在查看这一带…」），播放条右侧的 ⏭ 变转圈。
- **飞过去之后**：地图滑到台的位置，同时**保留松手处的准星 pin**，用一条细虚线连到电台 pin —— 让人看清
  「你选这里 → 最近的台在那里、多远」。
- **现在是同一台**：卡片里给它 ✓「正在播放」，不自动重播、不挪地图。
- 卡片可以下滑关闭；关闭后地图停在原处，不自动归位。

## 四、方案 B：「松手即播 + 说明」

保留零点击的快感，只补反馈：

1. 位移 < 24pt → 不换台。
2. 松手立即：播放条进入 `busy`（转圈 + 「正在找这一带的台…」），准星 pin 保留。
3. 结果回来：自动播放最近的台，地图滑过去；准星 pin 与电台 pin 用虚线连起来，300ms 后自动淡出。
4. 没有结果：**不打断当前播放**，弹一条 toast「这一带没有台，放大或移动地图再试」，地图停在原处。
5. 最近的台就是当前台：toast「已经是最靠近的台了」，不做任何播放动作。
6. 冷却 600ms：飞行中点地图 → 取消本次飞行与查询，从新的落点重新开始（而不是被吞掉）。

优点：一步到位；缺点：一松手就换台，在"随便看看"时容易丢台。

## 五、两方案的取舍

| | A 列表确认 | B 松手即播 |
| --- | --- | --- |
| 误换台风险 | 低（要点一行） | 中（松手就换） |
| 操作步数 | 拖 + 点 | 拖 |
| 发现感 | 强（能看到附近还有什么） | 弱（只看到一台） |
| 实现量 | 中（多一个卡片 + 列表） | 小 |
| 与「下一个」按钮的关系 | 不冲突：按钮=随机，地图=按距离 | 同左 |

我的建议：**A 为主干，吸收 B 的即时反馈** —— 也就是松手立刻出「正在查看这一带…」的卡片，
有结果时默认把"最近的那台"放在第一行并且**高亮但需点一下才播**；如果用户连续两次在同一个区域松手，
第二行以后保持列表。这样既不丢台，也不会有"点了没反应"的空窗。

## 六、待你拍板的三件事

3. **点击地图**（不是拖动）应该做什么？我的建议：只把准星移到点按处 + 显示"按住拖动看看附近"，不换台。
